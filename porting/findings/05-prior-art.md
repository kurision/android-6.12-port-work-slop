# 05 — Prior art

> **Historical record - undated.** This is what
> the evidence showed at the time and has not been rewritten. The
> current state is [CURRENT-STATE.md](../CURRENT-STATE.md).

Three bodies of code already exist for this chip. Knowing what each one is good
for saves weeks of blind work.

## 1. `msm8953-mainline/linux` — the closest thing to the goal

<https://github.com/msm8953-mainline/linux> — "Linux mainline kernel with WIP
patches for msm8953 devices", 151 stars, 109 forks, ~20 maintained branches.

**It has a `6.12/main` branch** (Makefile: `VERSION = 6, PATCHLEVEL = 12`), and on
that branch:

* `arch/arm64/boot/dts/qcom/msm8953.dtsi` and `pm8953.dtsi` exist;
* `msm8953-xiaomi-tissot.dts` (294 lines) exists, plus a shared
  `msm8953-xiaomi-common.dtsi` (469 lines) and board files for daisy, markw,
  mido, vince, ysl;
* the tissot DT enables a panel (`panel: panel@0`, `compatible = "xiaomi,tissot-panel"`),
  a sound card (`&sound_card`, `&wcd_codec`, `&max98927_codec`), touch
  (`&ft5406_ts`), sensors (`asahi-kasei,ak09918`, `liteon,ltr579`, `bosch,bmi120`),
  LEDs (`&aw2013_led`), haptics (`&pmi8950_haptics`), WLED (`&pmi8950_wled`),
  `cont_splash_mem` + `simple-framebuffer`, `&wcnss_iris` (`qcom,wcn3680`),
  `&sdhc_2`, `&spi_6`, `&uart_0`, and `&zap_shader`;
* 106 panel drivers under `drivers/gpu/drm/panel`;
* it still has **no** CPU clock gate work (`CPUSS` count 0 in the dtsi), no
  `tsens-8953` (`drivers/thermal/qcom` is byte-identical in spirit to upstream),
  and **no** Qualcomm WLED or haptics driver — so `&pmi8950_wled` and
  `&pmi8950_haptics` are inert there too.

Implication: a working 6.12 baseline for Mi A1 already exists. The interesting
question is not "can this be done on 6.12" but "android-mainline proper vs this
tree". Start from `6.12/main`, and treat android-mainline as an upstreaming
target.

## 2. `msm8953-mainline/linux-panel-drivers` — the panel problem is solved

<https://github.com/msm8953-mainline/linux-panel-drivers> (13 forks) holds
`dtb/xiaomi-tissot.dtb` plus generated mainline mipi-dsi panel drivers.
`config/xiaomi-tissot.sh`:

```bash
OPTIONS=(-r vsn -r vsp)
PANELS=(
        [ft8716_fhd_video]="mdss,ft8716-fhd"
        [otm1911_fhd_video]="mdss,otm1911-fhd"      # <-- this device's panel
        [ili7807_fhd_video]="mdss,ili7807-fhd"
)
```

Generated by `linux-mdss-dsi-panel-driver-generator` from the stock CAF DTBs.
This is exactly the panel in `artifacts/tissot-live.dts:1989`
(`mdss,otm1911-fhd`) with its VSP/VSN rails — do **not** write a panel driver
from scratch, port or reuse this one.

## 3. CAF/GKI 4.19 — `../kernel_xiaomi_msm8953`

`halcyonlv/kernel_xiaomi_msm8953` branch `16.2`, `4.19.325`, with
`arch/arm64/boot/dts/vendor/qcom/mi8953/tissot/tissot.dtsi` and
`arch/arm64/configs/vendor/tissot.config`. Good for:

* the stock CAF device trees (`arch/arm64/boot/dts/vendor/qcom/`) — the upstream
  source for all register/IRQ/pinmap values;
* 4.19-only workarounds (recent commits are `ARM64: dts: vendor: qcom: msm8953:
  update USB DWC3 node`, `configs: Enable CONFIG_USB_DWC3_MSM`).

Not usable as a 6.12 base: its driver stack is Qualcomm CAF.

## 4. postmarketOS 6.17.7-msm8953 — the behaviour oracle

The kernel this investigation booted on. Its `kconfig` (captured in
`artifacts/device-facts.tar`) shows what the reference stack actually uses:
`CONFIG_QCOM_TSENS=y`, `CONFIG_QCOM_CPR4PD=y`,
`CONFIG_REGULATOR_QCOM_LABIBB=y`, `CONFIG_DRM_PANEL_MDSS_OTM1911_FHD=m`,
`CONFIG_ATH10K=m`, `CONFIG_CPUFREQ_DT=y`, `CONFIG_ARM64_VA_BITS_48=y`.

That last panel symbol is worth noting: **the CAF panel driver for this exact
panel (`mdss,otm1911-fhd`) exists in that kernel's source** — another base for
phase 3 if the generated mainline driver does not fit.

## Decision input

| Base | Pros | Cons |
|---|---|---|
| `msm8953-mainline/linux` `6.12/main` | tissot support already written; panels solved; 6.12 | not android-mainline; needs mainline→android-mainline delta eventually |
| android-mainline `upstream-master` | official, clean, Android-targeted | tissot DTS does not even compile (`findings/04`) |
| CAF 4.19 (local tree) | full feature set | wrong kernel lineage for a mainline port |

Recommendation: prototype on `6.12/main`, then decide whether "android-mainline"
means the official tree (port forward) or just "a mainline kernel that boots
Android" (ship `6.12/main` + Android userspace).
